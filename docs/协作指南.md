# 四人协作指南（GitHub 协作者模式）

> 适用：可视化课程期末作业，4 人各负责 1 个页面，仓库 `rippleshe/AirObservatory`。
> 结论：**协作者模式可行**。仓库已完成一轮清理（第 1 节记录改了什么、为什么），剩下两件只有组长能做的事在第 1.5 节。

---

## 1. 仓库清理记录（已完成，2026-10）

清理的理由只有一条：**这几件事不处理，四个人一开工就会互相锁死，或者把密钥/百兆文件提交上去。**

### 1.1 `.env` 曾随仓库公开（高危）

- 仓库是 **public**（`rippleshe/AirObservatory`，`private: false`）。
- `.env` 曾被 Git 跟踪并已推送到 origin，内含 64 位真实 `OPENAQ_API_KEY`。
- `README.md` 曾写 “`.env` 已被 Git 忽略”，但 `.gitignore` 里根本没有 `.env` —— 文档与事实不符。

已处理：`.gitignore` 补上 `.env` / `.env.local`，并 `git rm --cached .env`（本地文件保留，后端照常读取）。

**但密钥本身必须由你本人更换**，见 1.5。

### 1.2 数据库曾入库（会导致无法合并）

- `HEAD` 里 `data/air_observatory.db` = **97.8 MB**，本地已长到 **244 MB**。
- GitHub 单文件硬上限 **100 MiB** → 下一次提交这个文件 push 直接被拒。
- 更致命：`scripts/worker.py` 每次采集都会写这个文件 → 每个人本地都显示 `M data/air_observatory.db` → **二进制冲突无法手工合并**，`git pull` 会永久卡住。

已处理：`git rm --cached`（本地文件与数据全部保留），`.gitignore` 增加 `data/*.db`、`data/*.db-journal`，并把已被跟踪的 `data/models/lstm_pm25_numpy-*.json` 一并取消跟踪。数据获取方式见 `README.md` 的「数据准备」。

统一约定：**每人本地 db 可以不同，但前端只读后端 API；最终演示与截图以一台机器的 db 为准。**

### 1.3 与课程无关的本机文件

`driver-backup/`、`install-ax201-driver.ps1`、`net-diag.ps1`、`frontend/scripts/*.tmp.mjs` 这些**从未被跟踪**，所以本来就不会出现在 GitHub 上，同学 clone 也看不到。为免以后 `git add -A` 误提交，已做两件事：加进 `.gitignore`，并把这些文件全部移出仓库目录到 `../AirObservatory-本机杂项/`（原文件保留，确认不需要后可直接删）。

`frontend/scripts/` 里真正有用、且已在仓库中的是 `visual-check.mjs`、`shot.mjs`、`crops.mjs`、`probe-dom.mjs`、`check-analysis.mjs`。

### 1.4 过期分支与冲突文档

- `marron` 分支（经确认是 `main` 的祖先、无独有提交）及其 `prunable` worktree 已删除。
- 与当前口径冲突的三份旧文档已删除：
  - `DESIGN.md` —— 公众用户假设，“不做论文式密集小图拼盘”；
  - `docs/SESSION_BRIEF.md` —— “文字越少越好 / 绝不科研绘图味”，且仍描述三个视图、引用了已不存在的组件；
  - `docs/REDESIGN.md` —— 与上者同源的旧规则。

  需要时从 git 历史取回；**四个页面的分支不得再引用这三份文件的规则**。

### 1.5 只有组长能做的两件事

1. **撤销并重建 OpenAQ key**：旧 key 已在公开历史里，视同泄露 → 去 OpenAQ 后台 revoke 并新建，再把新 key 写进本地 `.env`。
2. **给 `main` 开分支保护**：`Settings → Rules / Branches → Add branch ruleset`，开启 *Require a pull request before merging*（1 人 approve）+ *Block force pushes*。开了以后谁也推不动主干，合并权只在你手里。

> 可选（想彻底清历史再做）：`git filter-repo --path .env --path data/air_observatory.db --invert-paths` 后强推。这会让 97.8 MB 的历史 blob 和泄露的 key 从 GitHub 上真正消失，代价是所有人重新 clone。当前 `.git` 约 25 MB，不做也能正常协作。

## 4. GitHub 侧设置

1. **加协作者**：`Settings → Collaborators and teams → Add people`，填 GitHub 用户名，对方在邮件里接受邀请。public 仓库免费版协作者不限人数。
2. **保护 `main`**：`Settings → Rules / Branches → Add branch ruleset`，对 `main` 开启：
   - Require a pull request before merging（1 人 approve）
   - Block force pushes / Restrict deletions

   这样谁也推不动 main，只能 PR；合并权在你手里。
3. **CI 已经配好**：`.github/workflows/ci.yml` 在 push / PR 时跑两个任务——`backend · ruff + pytest`（uv + Python）与 `frontend · vue-tsc + vite build`（Node 22 + pnpm，版本取自 `frontend/package.json` 的 `packageManager` 字段）。PR 页面直接显示绿/红，你合并前不用手工验。协作者推第一个分支后确认 `Settings → Actions → General` 是开启状态；public 仓库免费。
4. 不需要写权限之外的额外配置；**不要**开 “Allow auto-merge” 之类自动合并。

## 5. 每个人每天的操作

```bash
git clone https://github.com/rippleshe/AirObservatory.git
cd AirObservatory
cp .env.example .env                   # 填自己的 OpenAQ key（.env 不入库）
git checkout -b page/overview          # 每人一条固定前缀的分支：page/city、page/analysis、page/forecast
```

开工前、提交前各做一次：

```bash
git fetch origin
git rebase origin/main                 # 先跟上主干再写，减少最后一次性大冲突
```

只提交自己的文件，**永远用明确路径，禁止 `git add -A` / `git add .`**（db 和 `.env` 当初就是这么被提交进去的）：

```bash
git add frontend/src/views/NationalOverviewView.vue frontend/src/components/ChinaFieldMap.vue
git commit -m "feat(overview): 时间机器与省代表联动"
git push -u origin page/overview
```

然后开 PR：`base: main ← compare: page/overview`，标题写清页面，正文贴验收结果。**由组长点 Merge。**

规模建议：不要一条分支挂一个月。按“一张图 / 一个交互 = 一个 PR”，1–3 天合并一次，主干始终是最新的，最后一周才不会在冲突里烧掉。

## 7. 最容易翻车的 5 件事

1. `git add -A` 把 244 MB 的 db 提上去 → push 直接被 GitHub 拒。
2. 各自跑 `pnpm run api:types` 覆写 `schema.d.ts` → 四人全冲突。
3. 直接往 `main` 推（没开分支保护）→ 别人的半成品被覆盖。
4. 长分支挂两周后合并 → 共享的 `palette.ts` / `base.css` 冲突堆积，最后一天通宵。
5. 有人为了自己页面好看直接改 `base.css` 的全局 token 或 `palette.ts` 的色值 → 另外三页同时变色，验收无法通过。

## 8. 密钥与数据：不进 Git 怎么给队友

先分清两件事：仓库里**已经有全部数据接口代码**（`backend/providers/`、`backend/pipelines/` 调用 OpenAQ / Open-Meteo / CAMS），队友 clone 就有；他们真正缺的是 **OpenAQ 密钥**和**数据本身**。

### 8.1 密钥（OpenAQ）

`.env` 永远不进 Git：仓库是 public，提交等于公开，别人能拿你的 key 消耗额度。分发只走私有渠道：

| 方式 | 说明 |
| --- | --- |
| 群 / 私聊直接发，各自 `cp .env.example .env` 后填入 | 最快；密钥只在你和三个队友之间 |
| 密码管理器共享条目（Bitwarden 等） | 可随时更换，不留聊天记录 |
| **队友连你的后端**（推荐，见 8.3） | 密钥不出你的机器，队友根本不需要它 |

密钥一旦发过群聊就当作半公开处理，学期结束后去 OpenAQ 后台轮换一次。

### 8.2 数据（数据库）

`data/air_observatory.db` 同样不进 Git（97.8 MB 超 GitHub 100 MiB 上限，且每次采集都写，入库必冲突）。队友要数据有三条路：

1. **连你的后端**（推荐）：一台机器跑 worker + API，其他人零配置。
2. 网盘 / Release 附件传一份 db 快照，各自放到 `data/air_observatory.db`。
3. 各自 `uv run python -m scripts.init_db` 加 `scripts.backfill_*` 重建（需要各自的 key，慢）。

### 8.3 共享后端：让队友只写一行配置

前端默认连本机 `127.0.0.1:8110`。只要在 `frontend/.env.local` 里写：

```
VITE_API_PROXY_TARGET=http://<跑后端那台机器的地址>:8110
```

`pnpm dev` 就会把 `/api` 代理到那台机器，界面读到的是同一套真实数据——本地不需要数据库，也不需要 OpenAQ 密钥。

- 局域网内填内网 IP；跨网络需要服务器或隧道（Cloudflare Tunnel / frp）。
- 若前端不走代理、而是从别的域名直连该 API，在后端 `.env` 设置 `AIR_OBSERVATORY_CORS_ORIGINS=http://<前端地址>`；不设置则不加 CORS 头，API 全是只读 GET，CORS 也只放行 GET。

四种方案里，只有 8.3 同时解决密钥和数据两个问题，也是答辩演示最稳的形态：**一台机器负责采集和出数，四台机器各写各的页面。**
