## 3. 开工流程（照着敲）

### 第一次：拉代码

```bash
git clone https://github.com/rippleshe/AirObservatory.git
cd AirObservatory
git checkout -b page/city          # 换成你自己那一页的分支名
```

`.env` 已经在仓库里了（含共用密钥），**clone 下来就能用，不要去复制 `.env.example`**——那会用一份空配置覆盖掉能用的密钥。

> 🤖 **用 AI 帮你写代码？** 先把 [`docs/AI协作提示词.md`](AI协作提示词.md) 里的提示词整段贴给它，作为新会话的第一条消息。里面已经把仓库规矩、你的文件范围、禁止事项都写好了，能挡掉 `git add -A`、乱跑 `api:types`、顺手重构共享文件这些常见坑。

### 之后每一轮开工前：先拉最新代码（这条最容易忘）

```bash
git fetch origin
git rebase origin/main
```

> 组长每次合并完会在群里说一声。看到通知就执行上面两行，把自己的分支"接"到最新主干上，然后再继续写。**不接的后果**：你写的东西基于旧代码，最后合并时全是冲突，谁也合不进去。

### 写完提交（只提交你自己的文件）

```bash
git add frontend/src/views/CityDetailView.vue frontend/src/components/HourRing.vue
git commit -m "feat(city): 小时热力改成时段选择"
git push -u origin page/city
```

**⛔ 禁止 `git add -A` / `git add .`** —— 会把数据库、编译产物一起提交上去。

### 然后开 PR

GitHub 仓库页面会提示 `page/city had recent pushes` → 点 **Compare & pull request** → 标题写清页面 → 创建。
**合并由组长点，你不要自己点 Merge。**

## 4. 关于数据库：随便搞，但别提交

数据**不在考察范围**里，所以你们不用为数据发愁：

- 本地数据库可以自己建、自己回填、四个人互不相同，都没关系；
- 想把图填满就直接造数据，不用问；
- 小提醒：图上那个来源标签（"地面实测" / "模式浓度换算"）别写反了，可视化作业会看这个。

**唯一不能做的是把数据库文件提交上来**，这不是规矩是技术限制：

- `data/air_observatory.db` 已经 **244 MB**，超过 GitHub 单文件 **100 MiB 硬上限**，`push` 会被直接拒绝；
- 而且采集程序每次运行都会写它，四个人的版本永远不一致，二进制文件**没法手工合并**，`git pull` 会卡死。
- 同理不要提交 `data/models/*.json`。

三种拿到数据的方式，挑一个：

1. **自己建**：`uv run python -m scripts.init_db`，然后按 `README.md` 里的 `scripts.backfill_*` 回填；
2. **连组长的后端**：在 `frontend/.env.local` 写一行
   `VITE_API_PROXY_TARGET=http://<组长的地址>:8110`，前端直接读他那套数据，你本地不用建库；
3. **网盘传一份** db，放到 `data/air_observatory.db`。

## 5. 每页要做到什么

总口径看 `PRODUCT.md` 和 `docs/科研可视化重构.md`（这两份是**唯一权威**，别的旧文档已删）。

**全国时空** —— 地图为主导航空口，点城市进详情；31 省代表的归约只在 `lib/provinces.ts` 里算一次再分发，标题里的省数、色带格数、地图点数必须描述同一个集合；时间切片所有图联动、同一个数据 cohort。

**污染过程** —— Pulse / Structure / Forecast / Trust 四区；**地面观测和模式分析分开成两条系列，不混成一条线**；缺数据就显示缺失，不要补造值把图填满；Trust 区展示覆盖率、Provider 绑定和时效。

**多变量关联** —— PCA 要给出解释方差、载荷、**样本量**和标准化方法；相关矩阵标注样本数与时间窗；聚类只作为探索线索，不要下"环境类型"的结论；风玫瑰说明风速分箱，**不推因果**。

**预测评估** —— 分清 CAMS 外部预测 / 本项目模型预测 / 地面真值三者；每个 horizon 给 MAE、RMSE、基线对比和样本数；回测用后来真正到达的观测值。

**数据与方法** —— provider health、站点绑定、采集批次、存储状态。

## 7. 组长的合并流程

1. 收到 PR → 看 diff 是不是只动了他自己那一页；
2. 等 CI 两个绿勾（`backend · ruff + pytest`、`frontend · vue-tsc + vite build`）；
3. 跑一遍 `pytest` + `pnpm run build` 确认；
4. 点 **Merge**；
5. 在群里通知大家执行 `git fetch origin && git rebase origin/main`。

## 8. 卡住了怎么办

| 症状 | 解决 |
| --- | --- |
| `pnpm run build` 报类型错误 | 看错误里提到的文件是不是你的；不是你的说明主干上有问题，找组长 |
| `git rebase` 冲突 | 不要瞎 `--force`；在群里说一声，让组长看一下 |
| `push` 被拒绝（文件太大） | 你八成提交了数据库，`git reset HEAD~1` 撤回，重新只 `add` 自己的文件 |
| 页面打开是空白 | 后端起来了吗？`http://127.0.0.1:8110/api/health` 有没有 `{"ok":true}` |
| 想改共享区的文件 | 单独开个小 PR，说明为什么非改不可 |
